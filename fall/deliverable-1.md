# Deliverable 1 — Kickoff and onboarding

**Week 4.** Tuesday is the intro deck, icebreakers, and how the lab's OpenRouter account and API keys work. Thursday is a short live demo of API calls, then the paper pool.

## Tasks

- [ ] Join the lab's OpenRouter organization and create your key:
  1. Sign in to [OpenRouter](https://openrouter.ai) with your **UCSC Google account**, the email the invite went to.
  2. Open the invite email and click the link while signed in. If it only shows the home page, check the account switcher at the top left. If **ACM** is listed, you are already in.
  3. Switch to **ACM** in the account switcher. A key made under your personal account has no lab credits.
  4. Go to **Settings → Keys → Create Key**, name it after yourself, and copy it right away.
- [ ] Create a GitHub repo for your lab work this quarter. Add a `.gitignore` that excludes `.env` before your first commit.
- [ ] Put the key in a `.env` file in that repo. Do not commit it or paste it anywhere else.
- [ ] Make a few working API calls through OpenRouter. Try at least two different models, and make at least one of them an open-weight model (for example Llama, Qwen, or DeepSeek). Keep the code and outputs.
- [ ] Read Zachary C. Lipton, [*The Mythos of Model Interpretability*](https://arxiv.org/abs/1606.03490) (2016).
- [ ] From the paper pool handed out Thursday, pick 1 or 2 AI safety papers you want to work from.
- [ ] Push your work to a `week-4/` folder in your repo, and write your one-page writeup.

## Done when

- You have a working key.
- You can show a few working API calls across at least two models.
- You have read *The Mythos of Model Interpretability*.
- You have named 1 or 2 papers from the pool.
- Your writeup and repo link are turned in, and the repo does not contain your key.

## Key rules

- Keys are for lab work only. Personal use gets the key revoked.
- Each member can spend $2 a week. The cap resets weekly.
- If you hit your cap doing lab work, ask a lead for more credit.

## Turn in

Turn in a one-page writeup and a link to your repo (`week-4/` folder), as described in [Turning in work](turn-in.md).
